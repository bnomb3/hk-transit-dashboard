# AGENT.md

This file provides guidance to coding agents when working with code in this repository.

## Commands

```bash
npm run dev     # Dev server at http://localhost:5173 with HMR
npm run build   # Production build to /dist
npm run preview # Preview production build locally
npm test        # Run tests in watch mode (vitest)
npx vitest run  # Run tests once (CI mode)
```

Update static data files (requires Python with `requests` and `opencc`):
```bash
cd scripts && python data.py
```

## Architecture

This is a **Hong Kong public transit ETA dashboard** — a Vite + React single-page app that polls live transit APIs and renders arrival times for multiple routes simultaneously. It has no backend and is deployed as a static site to GitHub Pages by `.github/workflows/deploy.yml`.

### Data flow

`App.jsx` holds `currentTime` (a timestamp that updates every hour) and `lang` (the display language). Both are passed as props to every panel component. Each panel re-fetches its data whenever `currentTime` changes.

The list of panels comes from `src/hooks/usePanels.js`, which loads it from `localStorage` (key `transit_panels`), falls back to `DEFAULT_PANELS`, and exposes `addPanel` / `removePanel` / `reorderPanels`. `App.jsx` maps each panel config to a component in `renderPanel()` and wraps it in `PanelWrapper` (drag handle and delete button in edit mode, via `@dnd-kit`).

### API routing

All API base URLs come from `src/api.js`; never hard-code `/api/...` or upstream URLs in components.

- In development, `API.*` resolves to `/api/*` paths, forwarded by the proxy in `vite.config.js`.
- In production builds, `API.*` resolves to the upstream endpoints directly. They all send `Access-Control-Allow-Origin: *`, which is what makes static hosting possible.

`vite.config.js` sets `base: './'` so the build works under a sub-path such as `https://<user>.github.io/hk-transit-dashboard/`. Keep asset references in `index.html` relative.

### Panel components

Each transport operator has its own panel in `src/components/`:

| Component | Operator | `API` key → upstream | Color |
|-----------|----------|----------------------|-------|
| `CTBPanel` | Citybus | `citybus` → `rt.data.gov.hk/v2/transport/citybus` | Yellow `#ffdd00` |
| `KMBPanel` | KMB | `kmb` → `data.etabus.gov.hk/v1/transport/kmb` | Red `#d93934` |
| `GMBPanel` | Green Minibus | `gmb` → `data.etagmb.gov.hk` | Green `#4da94d` |
| `MTRPanel` | MTR | `mtr` → `rt.data.gov.hk/v1/transport/mtr/getSchedule.php`; `mtrDuration` → `www.mtr.com.hk/share/customer/jp/api/HRRoutes` | Line-specific colors |
| `TimetablePanel` | Any user-defined service | None; departure times come from the panel config | Purple `#ab64a8` |

All API-backed panel components follow the same internal split: a `*PanelHeader` sub-component renders the table header (stop name, column labels), and a `*PanelBody` sub-component holds the fetch logic and renders ETA rows.

### Panel props

- `currentTime` — epoch ms; changing this value triggers a data re-fetch in every panel
- `lang` — `"en"` | `"zh-HK"` | `"zh-CN"`
- `route` — route number (KMB, CTB, GMB)
- `fromStop` / `toStop` — operator-specific stop IDs (`fromStation` / `toStation` as `"LINE-STA"` for MTR)
- `direction` — operator-specific direction value (e.g. `"UP"/"DOWN"` for MTR, `"outbound"/"inbound"` for CTB/KMB, `"1"/"2"` for GMB)
- `journeyDuration` — minutes; when set, panels display an "estimated off time" column (arrival + duration). MTR fetches this itself when `toStation` is set. `migratePanels()` in `usePanels.js` renames the old `duration` key and drops panels of the removed `shuttle` type.
- `serviceType` (KMBPanel only) — KMB service type, defaults to `"1"`
- `region` (GMBPanel only) — `"HKI"` | `"KLN"` | `"NT"`
- `name`, `from`, `to`, `weekdays`, `holidays` (TimetablePanel only) — display labels plus arrays of `"HH:mm"` departure times. `holidays` applies on Saturdays, Sundays and public holidays; when empty, `weekdays` applies every day.

### Add Panel wizard

`src/components/wizard/AddPanelModal.jsx` is a multi-step form that validates a route against the operator API, loads directions and stops, and calls `onAdd(config)` with an object in the same shape as the entries in `DEFAULT_PANELS`. The `timetable` type skips the API steps: one form collects the labels and free-text departure times, which `parseTimes()` in `src/timetable.js` normalises to sorted `"HH:mm"` strings.

### Static data files (`src/data/`)

- `mtrData.json` — MTR station list keyed by line/direction, plus line names in EN/TC/SC; generated by `scripts/data.py`
- `mtrStations.json` — flat station lookup; also generated by `scripts/data.py`
- `publicHolidays.json` — list of HK public holiday dates in `yyyyMMdd` format; generated by `scripts/data.py`

Run `scripts/data.py` whenever MTR station data or public holidays need refreshing.

### i18n

`src/i18n/config.js` initialises i18next with three locales (`en`, `zh-HK`, `zh-CN`) loaded from `src/i18n/locales/`. It also exports `updateLuxonLocale()`, which maps the app's lang codes to Luxon locale strings (`zh-Hant`, `zh-Hans`) so that relative time strings (e.g. "in 5 minutes") are localised. Every panel component calls `updateLuxonLocale(lang)` inside a `useEffect` on lang change.

All times are displayed in the `Asia/Hong_Kong` timezone using Luxon's `setZone()`.

### Adding a new panel

1. Create `src/components/XPanel.jsx` following the Header/Body split pattern.
2. Add the upstream URL and a dev proxy path to `src/api.js`, and the matching proxy rule to `vite.config.js`. Confirm the upstream sends CORS headers, or the panel will only work in development.
3. Add a `case` for the new type in `renderPanel()` in `App.jsx`.
4. Add the operator to the wizard in `AddPanelModal.jsx` and, if wanted, to `DEFAULT_PANELS` in `usePanels.js`.
